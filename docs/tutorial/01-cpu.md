## Panels to watch

- **Source** addresses and generated bytes
- **Instruction** mnemonic, opcode, length, and timing
- **CPU** PC
- **Bus** Opcode Fetch and Operand Read

## Goal

Connect source to machine code, follow fetch/decode/execute, and explain PC movement from instruction length.

## How the Z80 works

An instruction begins with an opcode and may contain immediate operand bytes. PC advances by the encoded size unless execution replaces it with a branch target.

## Try it with the CLI

```console
zig build run -- asm examples/add.asm -o zig-out/add.bin
zig build run -- disasm zig-out/add.bin
```

## Observe it in the TUI

```console
zig build run -- tui examples/add.asm
```

The generated sequence begins:

```text
0000  3E 0A   ld a,10
0002  06 14   ld b,20
0004  80      add a,b
0005  76      halt
```

`LD` is a mnemonic; A and 10 are operands. `3E` is the opcode and `0A` is the immediate byte.

### Step through it

```text
Step 1  LD A,10   PC 0000→0002, A 00→0A
        Bus: Fetch [0000]=3E, Operand [0001]=0A

Step 2  LD B,20   PC 0002→0004, B 00→14
        Bus: Fetch [0002]=06, Operand [0003]=14

Step 3  ADD A,B   PC 0004→0005, A 0A→1E
        Bus: Fetch [0004]=80

Step 4  HALT      PC 0005→0006, CPU HALTED
```

Fetch reads the opcode at PC; decode determines its operation and operand form; execute changes state; then PC advances or branches. ADD A,B is one byte because the register choice is encoded in its opcode.

## IDE Tips

- `Ctrl+R`: assemble in-memory source without saving.
- ADDR/BYTES describe the last successful assembly and may be stale while Dirty.
- Put the cursor on a mnemonic to inspect it without moving PC.
- `Ctrl+R` reassembles and reloads for observation from the start. `Ctrl+E` resets and immediately runs.
