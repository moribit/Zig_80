# Zig_80 Terminal UI

[日本語版](tui.ja.md)

The Zig_80 TUI is an additional frontend over the existing Core APIs. It does not replace the headless CLI and does not launch CLI commands as child processes. Both frontends call the assembler, CPU, Machine, disassembler, debugger state, and trace interfaces directly.

## Starting the TUI

```console
zig build run -- tui
zig build run -- tui examples/pixel.asm
```

The current implementation targets interactive ANSI/VT100-compatible terminals on macOS and Linux. Recommended size is 80×24 or larger. Smaller terminals use a single-panel layout; extremely small terminals show a size warning. Non-TTY stdin or stdout is rejected before raw mode or alternate-screen sequences are enabled.

The terminal session saves the original `termios`, disables canonical input, echo, signals, and CR conversion, then enters the alternate screen and hides the cursor. Ctrl+C is decoded by the application as Quit. A deferred session cleanup restores attributes, cursor visibility, the primary screen, canonical mode, and echo after normal or error exits.

Windows console support has a separated extension module but is not currently implemented.

## Layout

At normal sizes the screen contains:

- a quiet two-line header containing only the application, file, and modified state;
- a source-first editor occupying roughly 70% of the normal layout, with separated gutter columns;
- compact vertical CPU and Instruction cards;
- a lower Bus, Memory, Display, Help, or Diagnostics panel;
- a badge-style execution/status line with pane-local context help.

At compact sizes, `Ctrl+1` through `Ctrl+5` switch the whole content area between Source, CPU, Memory, Bus, and Display. This depends on a terminal that reports modified digits (CSI-u).

Rendering uses reusable previous and next Frame Buffers. Widgets write cells only; they do not emit ANSI. The renderer compares frames, builds one buffered ANSI update, and writes only changed cells. `NO_COLOR` and `TERM=dumb` disable color. The UI uses ASCII borders and an ASCII display fallback so meaning does not depend on color or Unicode.

## Basic keys

| Key | Operation | Alternative |
|---|---|---|
| `Ctrl+S` | save source | — |
| `Ctrl+Q` | quit | `Ctrl+C` |
| `Ctrl+R` | assemble | palette: `assemble` |
| `Ctrl+E` | run from reset | palette: `run` |
| `Ctrl+T` | step one instruction | palette: `step` |
| `Ctrl+Space` | continue | palette: `continue` |
| `Esc` | pause | cancels an active input mode first |
| `Ctrl+B` | toggle source breakpoint | `b` outside Source |
| `Ctrl+P` | command palette | `:` outside Source |
| `Tab` / `Shift+Tab` | indent / unindent in Source | next / previous pane elsewhere |
| `Ctrl+1..5` | Source, CPU, Memory, Bus, Display | — |
| `Ctrl+Z` / `Ctrl+Y` | Undo / Redo | — |
| `Ctrl+F` | incremental literal search | — |
| `Ctrl+]` | jump to label definition | `Enter` on a label reference |
| `Alt+Left` / `Alt+Right` | jump history back / forward | — |
| `Shift+Arrow` | extend Source selection | — |
| `?` | help outside Source | inserts `?` in Source |

Arrow, Home, End, Delete, Backspace, Page Up, and Page Down keys edit or navigate the active view. Quitting with unsaved edits requires a second `Ctrl+Q`; saving or another command cancels that confirmation.

The Memory view uses arrows to move the starting address. Press `g` to open the visible `Go to address: 0x____` mode, enter exactly four hexadecimal digits, and confirm with Enter. Backspace edits and Escape cancels it; other characters are ignored. Home jumps to PC, End to HL, Page Up to SP, and Page Down to VRAM at `0xC000`.

The Bus view uses `[` and `]` for event selection, End for latest-event follow mode, and Enter to move to the selected event's exact source PC when a mapping exists. At normal width Event Group and Logical Waveform are simultaneous. All modes share selection and latest-event follow state.

## Assembly and debugging

A non-empty source is assembled immediately when opened, so the first frame already shows its generated instruction at PC 0000. Failure keeps the editor open and shows Diagnostics. Subsequent edits only mark the source and status as DIRTY; the source title labels the loaded build as stale. Ctrl+R assembles without saving, while Ctrl+S saves and then assembles.

The Source gutter always reserves independent symbol columns for breakpoint (●), current PC (▶), diagnostic (!), previous instruction (▲), and edit cursor (┃). At sufficient width it also shows generated address and up to three bytes before the source; those columns disappear on narrow panes.

### Z80-aware Source editing

The gutter separates `BP`, `PC`, diagnostic, last-executed, edit-cursor, `LINE`, `ADDR`, and `BYTES` columns. The edit cursor (`┃`), current PC (`▶`), breakpoint (`●`), diagnostic (`!`), and last executed instruction (`▲`) are independent; current-PC text receives restrained emphasis rather than being confused with the editing line. Generated bytes also appear in a subdued inline suffix after assembled source when space permits.

Fixed-width marker, line, address, and byte groups are separated by visible `│` rules and at least one space. The editing line uses one low-intensity reverse band from the first gutter cell through the right margin, including otherwise empty line-end cells. Current PC remains a green marker plus bold source, so execution and editing locations remain distinct when they overlap. Address, bytes, and line numbers share a subdued auxiliary style; labels use the structural accent and bold weight. A reserved 12–18-column right margin prevents source text from crowding the pane edge and provides a stable home for inline execution or diagnostic overlays.

An assembler-independent tokenizer classifies labels, mnemonics, registers, numbers, directives, comments, strings, and character literals. A 128-slot line cache hashes visible source lines, so unchanged lines are not tokenized again each frame. `NO_COLOR` removes emitted ANSI colors without removing structural markers.

Completion is refreshed on edits, allocates no memory per candidate, and uses the current instruction position:

- the instruction field offers mnemonic and directive prefixes;
- operands offer registers filtered for forms such as `PUSH`/`POP`, branch conditions and source labels for jumps, and address registers after `LD (`;
- labels are collected from both `name:` and `name equ value` definitions across the source;
- Up/Down selects a candidate, Space accepts it and adds a separator, and Enter accepts it without adding a newline.

Enter preserves the previous indentation; a label followed by Enter starts its body with four spaces. Tab and Shift+Tab indent or unindent the current line or selected range. Shift+Arrow creates a selection. Ctrl+Z and Ctrl+Y navigate a bounded 64-snapshot edit history.

Ctrl+F opens a small incremental literal-search bar; Enter finds the next occurrence and Escape closes it. Enter on a known label reference or Ctrl+] jumps to its definition. Alt+Left and Alt+Right navigate the bounded jump history. `Go Line`, `Go Label`, `Rename Label`, `Search`, `Breakpoint`, `Assemble`, and `Run` are available from the command palette. Rename performs a token-boundary replacement of definitions and references while skipping comments, strings, and character literals.

Assembler failures remain shared structured diagnostics, but the failing span and message are also rendered inline. Hovering the edit cursor over a mnemonic redirects the Instruction card to that source instruction without changing PC. Step keeps the independent editing cursor in place, scrolls the current PC into view, and briefly annotates the executed source line with an observed register change, memory write, or `HALT`. `execution_overlay_enabled` keeps this feature independently switchable for a later settings UI.

Assemble operates on the in-memory editor contents. Success stores the generated bytes, symbols, and source-line/address mappings and loads the same `Machine` used by the CLI Core. Failure leaves the text intact and shows the shared structured diagnostic with file, line, column, source line, and hint. Enter on the diagnostic moves the editor to that source line. Diagnostic strings are owned independently of the editable buffer, and AppState stores a diagnostic list even though the assembler currently stops at its first error. The CLI assembler prints the same structured location rather than parsing TUI text.

Run executes cooperatively in slices of at most 500 instructions per UI tick, so infinite Z80 loops do not block terminal input. Pause, Continue, Step, Reset, and source breakpoints share a reusable `DebugSession`. Source highlighting occurs only when PC exactly matches an emitted instruction address; otherwise current disassembly remains authoritative.

Across all cooperative slices, Run and Continue default to limits of 10,000,000 executed instructions and 100,000,000 total CPU T-states. Reaching either changes the state to `LIMIT REACHED` and reports both counters. Reset clears the counters. Step is defined as an explicit override: it may execute one instruction after a limit stop and leaves execution paused. Limits live in `ExecutionLimits` so a later CLI option or settings UI can replace the defaults without changing execution logic.

The Display panel reads the existing 128×64, 1bpp VRAM through the Machine's established pixel layout. It does not add terminal behavior to CPU or Machine. The command palette selects 1x, 2x, or 4x presentation (2x by default) and toggles an 8-pixel grid at scales 2x and above. Larger scales use a cursor-centered viewport rather than changing VRAM semantics.

Its status line reports dimensions, format, scale, monotonically increasing VRAM-update frame, pixels changed by the latest update, and display-update FPS. FPS counts VRAM updates, not CPU execution or terminal refreshes. While Display is focused, arrows inspect a pixel and show its x/y, VRAM address, bit, current value, and the latest observed writer instruction. The game area is centered whenever the complete scaled image fits. Changed pixels, the Instruction card, source execution overlay, and register differences share a roughly 300 ms execution emphasis. `NO_COLOR` substitutes temporary symbols for dirty pixels, and the Display title briefly gains an update marker.

Each Step records an observed instruction result in the TUI layer. The source margin shows the register or memory result, CPU renders current and previous values, Bus follows the latest event, and Display marks changed pixels without introducing device behavior into Core. A bounded instruction-snapshot table links a selected Bus event back to its PC and CPU before/after state; selecting a VRAM write also moves the Display inspector to that byte. On terminals at least 32 rows high, the normal Bus dashboard keeps Source, CPU, and Instruction visible; shorter terminals temporarily devote the body to Bus so all waveform rows remain legible.

The CPU card groups control registers (`PC`, `SP`), leaves a blank rhythm line, then groups `AF`, `BC`, `DE`, and `HL`. Flags form a vertical state column. Changed registers render old value, downward transition, and new value with temporary emphasis. The adjoining Instruction card makes the mnemonic its primary heading, then uses one consistent auxiliary label style for Address, Opcode, Length, Timing, Description, and Flags while values retain normal or bold text weight.

Focused pane titles use reverse video. Titles include live state, such as `SOURCE (Assembled)`, `CPU (Halted)`, `BUS (7 events)`, and `INSTRUCTION (0006)`. The header deliberately contains no shortcut list: it shows `Zig_80 IDE`, the current path, and a separate Modified marker only. Pane-local help moves to the right side of the status bar. Ctrl+P opens the command-centered palette containing Source navigation/editing actions, execution actions, view switches, and Quit. In Source, literal `:`, `?`, `b`, and `g` remain editable text; their single-key UI commands apply outside Source, while Ctrl+P and Ctrl+B remain global. Action results appear as a fixed-buffer toast for about two seconds. The status bar visually separates state and cleanliness badges from named `PC`, `Instr`, `T-State`, and `Trace` metrics.

## Bus Trace accuracy

> Bus Waveform visualizes logical bus accesses observed during instruction execution as equal-width events. It does not reproduce real Z80 electrical timing or the duration of individual T-states.

The optional Core `TraceSink` records opcode fetches, immediate operand reads, memory reads, and memory writes. I/O, refresh, and interrupt event kinds are reserved for future work. Events use a fixed 4,096-entry ring buffer and allocate no memory per access; old entries are discarded when full. A zero event duration explicitly indicates that no cycle duration has been modeled.

The event list includes the instruction index, logical event index within that instruction, instruction-start T-state total, kind, address, data, PC, and modeled signals. `t_state_start` is the CPU total at instruction start, not the access time. `t_state_count == 0` means unmeasured logical access.

When focused at normal width, Bus places an Instruction card beside the Logic Analyzer. The card reports PC, decoded Mnemonic, Opcode bytes, total event count, Memory access count, and I/O access count before listing accesses belonging to the selected instruction with their within-instruction index.

The Logic Analyzer makes `Time →` the primary axis and groups slots under `Instruction #` headings. Active-low controls are labeled `/MREQ`, `/IORQ`, `/RD`, `/WR`, and `/RFSH`; an asserted logical access is drawn as a low pulse. `┐`/`└` and `┌`/`┘` pairs expose falling and rising edges, while short panes use a compact trace. Address and Data use aligned `[0000]` and `[00]` bus boxes. The selected event has one thin, single-cell `│` time cursor through headings, signals, and buses (`|` in ASCII), followed by a PC/kind/data detail line. `+`/`-` changes 1x, 2x, and 4x zoom, `f` selects Fit, and Shift+Left/Right or `<`/`>` pans independently of the cursor. Fit samples the complete logical sequence into available terminal columns when necessary. Pulse widths are equal logical slots—not measured electrical time.

Before events exist, the Bus area contracts beside a Getting Started pane; it expands automatically after Step or Run. UTF-8 locales use line/block glyphs and merged pane junctions, while other locales use ASCII. VCD export remains future work and requires more accurate source data. The execution overlay can be enabled or disabled from the command palette.

The command palette can show all Bus event kinds or only Memory Write. Filtering applies to the grouped list, waveform slots, and arrow navigation while preserving the shared underlying selection. Opcode Fetch, Operand Read, Memory Read, Memory Write, I/O Read, and I/O Write have independent filter fields for later settings UI.

The input layer uses one persistent, allocation-free 256-byte stream decoder. It retains incomplete UTF-8 and escape sequences across reads, distinguishes a lone Escape after a short terminal-layer timeout, and supports split Alt keys. Invalid UTF-8, unknown completed sequences, and overflow are discarded or bounded so later keys can still be decoded.

## Current limitations

- Completion uses a broad Z80 vocabulary for learning, while the current assembler implements only its documented subset; selecting a mnemonic such as `LDI` can therefore still produce an assembler diagnostic.
- Search is literal and case-sensitive. Undo/Redo uses bounded full-source snapshots rather than edit coalescing.
- No clipboard operations, mouse input, or multiple files.
- UTF-8 source is kept valid and can be edited, but terminal column widths for full-width and combining characters are not modeled.
- No watchpoints, step over/out, time travel, asynchronous execution, or hardware USB debugging.
- Historical CPU linking is bounded to the latest 4,096 instruction snapshots. Display linking identifies a selected VRAM byte in current Machine memory; it is not a time-travel reconstruction of an old frame.
- Bus waveform slots are logical accesses, not electrical or cycle-accurate timing; I/O, refresh, and interrupt events are not emitted yet.
- Diagnostics stop at the first assembly error and do not yet provide secondary notes or fix-it edits.
- Resize is detected by periodic terminal-size checks rather than a `SIGWINCH` handler.
- Windows is not supported.
